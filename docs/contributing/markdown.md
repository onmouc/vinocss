# Markdown

Format rules for markdown files, these guides included.
Read before creating or editing any `.md` file.
A guide also follows [guidelines](./guidelines.md), which covers the guide system itself.

## Tone

1. Write for ai tools and developers of varying experience.
2. Prefer structure over prose; let headings and lists carry the rules.
3. State rules directly; cut greetings, framing, and filler.
4. Keep each file to one core topic.

## Lines

1. Break a line at a clause or sentence boundary.
2. Follow the punctuation: break after a comma, a semicolon, or a closing period.
3. Never break mid-clause to reach a width; let a short line stay short.
4. Avoid leaving a single word or a detached fragment on a line.

## Paragraphs

1. Avoid a single-sentence paragraph; pair it with a related sentence.
2. Avoid a long paragraph; split it at a topic change.
3. Let lists carry rules, and let prose carry the reasoning behind them.

## Lists

1. Prefer an ordered list for a sequence of three or more items.
2. Use an unordered list for fewer than three items, for a strictly unordered set,
   or for a list that runs past nine items.
3. Keep each item to one line, and put extra detail in a paragraph below.
